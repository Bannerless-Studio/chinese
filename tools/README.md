# tools/ — Chinese (HSK) data build scripts (dev/agent notes)

Purpose: the two hand-run scripts that build and validate this repo's
`data/` files, which `vocab-engine/tools/pack_from_hsk.py` then reads to
produce `pack/`. Unlike the other language repos, there is no packbuilder
here (no `langs/zh.py`); the vocabulary and sentences are curated in this
repo's `data/`, not corpus-mined at build time.

## Hand-run scripts

- `build_vocab.py` — regenerates `data/hsk_vocab.json` and
  `data/hsk_vocab.js` (the HSK 1-4 vocabulary, ~1200 words) from the
  community [complete-hsk-vocabulary](https://github.com/drkameleon/complete-hsk-vocabulary)
  dataset (`complete.json`, downloaded fresh or supplied via `--source`).
  It picks one English sense and one pronunciation per word (surname/rare
  readings and variant-of glosses are filtered) and prints per-level
  counts, validation stats and a diff against the previous
  `data/hsk_vocab.json`. Run with `python3 tools/build_vocab.py`.
- `check_sentences.py` — validates `data/hsk_sentences.js` (hand-authored,
  not generated) against `data/hsk_vocab.json`: segmentation, a pinyin
  cross-check (with documented tone-sandhi exceptions for 不/一), no
  duplicate sentences, per-level length limits, and >=70% vocabulary
  coverage. It also resolves `SENTENCE_EXTRA` compounds (e.g. 春天, built
  from the VOCAB word 春 plus a bound suffix that isn't its own VOCAB
  entry) against their declared `base` word. Run with
  `python3 tools/check_sentences.py`.
- `check_patterns.py` — validates `data/hsk_patterns.js` (hand-authored
  grammar patterns, CC-BY-SA-4.0 like the sentences) with the same
  segmentation, level and pinyin rules, plus pattern fields (ids p01..,
  level order, two-line note of at most 60 characters, `near` ids, 6-8
  sentences of 3-14 characters, no duplicate of hsk_sentences.js, `marks`
  on word boundaries). Compounds only pattern sentences use go in the
  file's `PATTERN_EXTRA` (not `EXTRA`, which becomes the engine's
  `pack.compounds`). Run by `check.sh`. Run with
  `python3 tools/check_patterns.py`.

## Not generated by these scripts

- `pack/` (the engine pack) is a generated copy of `vocab-engine/packs/zh`,
  produced by `vocab-engine/tools/pack_from_hsk.py` reading this repo's
  `data/` — not by anything in this directory.
- `pack/passages_src.json` and `pack/REPORT_passages.md` are kept in the
  pack directory (not `tools/`) so the 60 reading passages can be rebuilt;
  see vocab-engine's packbuilder passages tooling.

## Legacy pre-switch pipeline (kept for history and rollback)

Everything below describes the pre-switch single-file app, superseded by the engine-based build above. Its sources (`src/`, `data/`, `tools/`, `tests/`, `docs/`) are kept for history and rollback. Its builder is now `build_legacy.sh`; the new `hsk_pinyin.html` stub and `index.html` are no longer its outputs.

### Files

- `index.html` / `hsk_pinyin.html` — **the app**, identical self-contained builds (`index.html` exists so GitHub Pages serves it at the site root). Data and helpers are inlined. Open directly from `file://` or serve as static files.
- `src/pinyin_app.html` — dev version of the app. Loads `data/hsk_vocab.js`, `data/pinyin_lessons.js`, and `src/pinyin_core.js` via `<script src>` so they can be edited independently. Also works from `file://`.
- `src/pinyin_core.js` — pure-JS pinyin helpers (syllable split/marking, valid-syllable table, meaning-distractor and pinyin-distractor pickers, phonetic distractor generation for Extras, type-answer normalization, placement scoring, progress-shape validation). No DOM dependency; usable from both the browser and Node.
- `data/hsk_vocab.js` — `const VOCAB=[{w,py,n,en,lv}]`, HSK 1–4 vocabulary (~1200 words). Regenerated by `tools/build_vocab.py` (see its docstring for the source dataset, sense-selection rules, and the manual override table).
- `data/pinyin_lessons.js` — `const LESSONS=[...]`, the 12-lesson "Sounds" curriculum.
- `data/hsk_sentences.js` — `const SENTENCE_EXTRA={...}` (compound tokens not in `VOCAB`, each with a `base` VOCAB word) and `const SENTENCES=[{zh,py,en,lv,words}]`, ~880 short example sentences built from HSK 1–4 vocabulary. Validated by `tools/check_sentences.py`.
- `build_legacy.sh` — inlines `data/hsk_vocab.js`, `data/pinyin_lessons.js`, `data/hsk_sentences.js`, and `src/pinyin_core.js` into `src/pinyin_app.html`, producing `hsk_pinyin.html` and a copy at `index.html`.
- `tests/pinyin_checks.js` — Node script exercising the real helpers against the real data (see below).
- `tools/check_sentences.py` — Python validator for `data/hsk_sentences.js` (segmentation, pinyin cross-check, dedup, length limits, vocab coverage) against `data/hsk_vocab.json`. Run with `python3 tools/check_sentences.py`.
- `docs/PINYIN_SPEC.md` — design spec for the pinyin trainer (source of truth for behavior; deviations noted at the bottom).

### Build

```
OUT=/tmp/x.html INDEX=/tmp/y.html ./build_legacy.sh
```

Regenerates `hsk_pinyin.html` and `index.html` from the current `src/` and `data/` files (including `data/hsk_sentences.js`). Requires only `awk` (no Node needed to build, though Node is used for checks).

### Run

Open `index.html` (or `src/pinyin_app.html` for development) directly in a browser — no server needed. Progress is stored in `localStorage` (or `window.storage` if the host page provides that shim).

Supported browsers: Chrome, Firefox. Samsung Internet has no working speech synthesis — the app shows a notice and text-based drills still work, but audio doesn't play.

### Deploy

GitHub Pages is configured to serve from the `main` branch root. Deploying is: run `./build.sh` to refresh `index.html`, commit, and push to `main` — no separate deploy step or CI action.

### Checks

```
/opt/homebrew/bin/node tests/pinyin_checks.js
```

Runs, against real `data/` files:
0. Stale-build guard: rebuilds `src/pinyin_app.html` via `build.sh` to a scratch location and diffs it byte-for-byte against the shipped `hsk_pinyin.html`/`index.html`, so an edit that was never followed by `sh build.sh` can't slip a green check run past a stale bundle.
1. `mark(n) === py` for every `VOCAB` entry (tone-mark placement + apostrophe-boundary rule), reporting any mismatches.
2. Phonetic distractor generation (the Extras tone/type generator) over 200 random words — every distractor is a valid, distinct syllable string that isn't the answer and has the same syllable count.
3. `normType`/`acceptTypeAnswer` accepts the documented input variants (numbered, marked, mixed case, `ü`/`v` equivalence, omitted/`0` neutral tone) and rejects wrong tones.
4. Placement strata bucket math (40 vocab items across 16 buckets: L1×3, L2×3, L3×4, L4×6), via the shared `PC.strata`.
5. Erhua regression: 一会儿 (a trailing bare "r" syllable) gets real tone-swap distractors, not the rule-4 different-word fallback.
6. No phonetic distractor puts a neutral (5th) tone on a word's first syllable, checked across the full corpus.
7. `validateProgShape` rejects malformed imports (`null`-valued `w`/`sets`/`lessons`, a bare array) and accepts a real export shape.
8. `placementStopIndex`'s rolling-window pass rule on synthetic bucket results (all-correct passes everything; an all-wrong bucket stops there; a single miss in a big-enough bucket still passes).
9. `meaningOpts` (the hear/read meaning-distractor picker) over 200 random words — 3 options, all real VOCAB entries, none equal to the answer's gloss, none sharing the first two gloss words with the answer or each other; reports the same-level ratio.
10. `pinyinOpts` (the recall pinyin-distractor picker) over 200 random words — 3 options, all real VOCAB entries, same syllable count, never the answer.
11. v1 → v2 progress migration: `validateProgShape` accepts both a v1-shaped and a v2-shaped export, and a v1 export migrates to a well-formed v2 progress object (`v:2`, `showChars:false` default, word/set/lesson data preserved).
12. Gloss-sanitizer regression gates: no `VOCAB` `en` field contains a leaked CJK character, and none matches the dangling-lead-in pattern (`equivalent to`, `opposite`, `abbr.`, etc. left stranded by a stripped clause), aside from two documented, allowlisted false positives (对面, 相反); plus unit tests for `PC.gloss()`'s render-time CJK guard.
13. Every `words` token in every `SENTENCES` entry resolves to a real `VOCAB` word or a `SENTENCE_EXTRA` compound whose `base` is in `VOCAB` — checked across all 882 sentences.
14. `sentenceOpts` (the sentence meaning-distractor picker) over the full sentence corpus — 3 valid options, all real sentences, none equal to the answer's gloss, deduplicated; reports same-level and shared-word preference ratios.
15. `PC.SENTENCE_FUNCTION_WORDS` matches the spec's exact list; `gapCandidateIndices` never offers a function word or a word that recurs elsewhere in the same sentence as the blank (the latter would leave the answer visible at its other occurrence) — checked across all sentences plus a synthetic duplicate-word case.
16. `gapOpts` (the fill-in-the-blank distractor picker) over every eligible gap candidate in the corpus — 3 real `VOCAB` entries, same syllable count as the answer (with a closest-count fallback for syllable counts with fewer than 3 corpus peers, same as `pinyinOpts`), never the answer.
17. `sentenceTokens`'s pinyin↔words alignment (`sentence.py.split(" ")` lining up 1:1 with `sentence.words`) holds across all 882 sentences.
18. Sentence-render capitalization regression guard: a Node-side mirror of `sentencePyHTML`'s render pipeline (tags stripped) equals each sentence's stored `py` with its first letter uppercased, across all 882 sentences — catches the 阿姨 ("āyí" → "āYí") class of bug where capitalizing "the first letter" landed on the wrong syllable.
19. `guessTone` unit cases covering `SENTENCE_EXTRA`-shaped compounds (neutral-tone suffixes like "-men"/"-ge", multi-syllable words, and the untoned fallback).

20. Phase 3/3b migration: a v1 export, a v2 export without `c`/`mixChars`, a v2.2 record, and a record with the Phase 3b path flags keep every existing field deep-equal through `validateProgShape` + `migrateProg`, gain only the documented defaults (`c:{}`, `mixChars:true`, `charsAfterHsk4:false`, `charsChoiceSeen:false`) when absent, and round-trip idempotently.
21. `validateProgShape` accepts well-formed and rejects malformed `c` (character progress) and `mixChars`.
22. `charOpts` (pickChar tile distractors) over 200 random words — 4 distinct words, all VOCAB, none sharing the answer's gloss or pinyin; reports same-level ratio.
23. Mixed-script tier decision (`PC.charTier`/`PC.sentenceTokenTier`): pinyin below streak 3, ruby 3–5, bare characters at 6+, pinyin whenever characters are locked or mixing is off.
24. Characters gate: placement strata end exactly at each level's set count, so placement past HSK 3 unlocks `PC.charsUnlocked` and makes 字 (HSK 1–3) the current stage (`PC.charsStarted`); one set short stays locked.
25. `newCharWords` ordering (Test → Characters top-up): skips recorded words, HSK 1 first then VOCAB order, capped.
26. Phase 3b path flags: `validateProgShape` accepts boolean / rejects non-boolean `charsAfterHsk4`/`charsChoiceSeen`; `migrateProg` defaults them false and keeps every old field.
27. Stage sequencing (`PC.stagePath`/`PC.nextStage`/`PC.charsStarted`): locked mid-level, HSK 3 done → 字 1–3, characters 1–3 done → HSK4, HSK 4 done → 字4, `charsAfterHsk4` → HSK4 then 字 1–4, all done → null; path order and stage fractions.
28. Character sets (`PC.charSets`/`charSetTaught`/`nextCharSet`): chunks of 10, HSK 1 first then VOCAB order; a set is taught iff all its words have `prog.c` records.
29. Unified Review ranking (`PC.rankReview`): a missed word outranks fresh characters, which outrank mastered words; unmastered characters score at least 0 (`PC.charReviewScore`), tying with never-drilled words.
31. Choice-card gating (`PC.showCharChoice`): shown iff unanswered, order not switched, HSK 1–3 done, HSK 4 not, and 字 1–3 incomplete — regardless of character records.
30. `recallCharOpts` (recallChar tiles) over 200 random words: 4 distinct characters, answer present, no distractor sharing the answer's `en` or pinyin.

Current result: **0/1193 mark() mismatches, all 33 checks pass (0–32).**
